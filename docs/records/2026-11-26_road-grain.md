# 道路の路面のざらつきを細かくした記録（2026-11-26）

[#81](https://github.com/128-bit-net/pak256/issues/81)。ユーザーの指摘（2026-11-25）: 道路が線路に比べて荒っぽく、バラストの粒の細かさと比べると、128 の絵をそのまま拡大したようなざらつきがある。

## 原因

- AMI の道具は、路面の模様（ノイズ）の細かさを「部品の座標」で決める。256 は同じ世界の大きさを画素 2 倍で描くので、模様の粒も画素で 2 倍に伸びる。
- 道路の路面（`tools/blender/sheetlib/road_parts.py` の `asphalt_skin`）は、ノイズの Scale が 60 のままで、色の段も狭い（0.47〜0.53）。2 倍に伸びた粒が、3〜4 画素の虫食い状のまだらになった。
- 線路のバラスト（`render.py` の `BALLAST_GRAIN`）も 2 倍に伸びるが、元の粒が約 1 画素で、2 画素の細かい砕石に収まるので目立たない。
- 歩道のアスファルト（`render.py` の `SIDEWALK_PAVINGS["asphalt"]`）も同じ作りで、同じ粗さだった。

## 直したこと

AMI の道具を、`SCALE`（pak128 で 1、256 で 2）を掛ける形に直した（pak256 は AMI の道具の直しを持たないので、AMI の側で直してもらった。128na/simutrans-addon-dev#288・PR #289・#290）。

- 路面: `scale=60` → `scale=60 * SCALE`
- 歩道のアスファルト: `scale=60` → `scale=60 * R.SCALE`

pak256 は、AMI の cc01310 から 256 版を組み直し（`ami-256-alpha.4`。`tools/build_ami256.py`）、`vendor/ami/build.env` と `ami.env` を上げた。

## 確かめたこと

- 128 が変わらない: 路面の道路 4 種（local・general・trunk・expressway）と歩道 4 種の 128 のシートを描き直し、コミット済みの PNG とバイト単位で同じ（AMI の PR で確かめ、pak256 でも同じ結果）。
- 256 の絵: 道路と歩道の粒が、バラストと同じ細かさのまだらになった。
- alpha.3 との違い（`build_ami256.py compare`）: pak は 7 つで名前も同じ。`ami_road.pak`・`ami_extra.pak`（歩道）は大きさが同じで中身が違う（粒の絵）。`ami_rail.pak` は、AMI の別の変更（#278 の線路の信号 `ami_rail_signal`）で 1 物増え、47 物になった。
- ゲームの画面（OTRP v64、`flat_512_left_v64`、`gui.set_zoom(3)`、`tools/game.py`）。道路 `ami_road_local` を (40, 40)〜(52, 40) に、線路 `ami_rail_ballast` を (40, 42)〜(52, 42) に敷き、(46, 41) へ移動して撮った。

## 確かめていないこと

- 道路の雪の粗さ。路面の雪（`ROAD_SNOW`、`render.py` の `scale=60.0`）にも `SCALE` が掛かっていない。試しに掛けると 256 の雪の粒がわずかに細かくなる（128 は変わらない）が、振れ幅が小さく差は目立たないので、この PR では直していない。
- 走行跡・路面表示は、路面と同じ材質なので一緒に細かくなったことを、シートの拡大で見ただけ（ゲームでは道路の走行跡だけ見た）。
- 歩道・路面表示・雪のゲームでの画面。
- 道路の見た目が線路と並んで見劣りしないかは、ユーザーが確かめる（`check:user`）。
