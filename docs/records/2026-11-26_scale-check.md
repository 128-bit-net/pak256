# 縮尺（1 単位 = 1.65m）の見比べ（2026-11-26）

[#104](https://github.com/128-bit-net/pak256/issues/104)。車両・街の建物・駅・停留所・産業・成木を同じ地図に並べ、昼の画面で釣り合いを見た。**縮尺を確定するのはユーザー**で、この記録は材料と案。

## 手順

1. `python -X utf8 tools/build.py` で組む（AMI の 256 版 `ami-256-alpha.5` を含む）。
2. `python -X utf8 docs/records/2026-11-26_scale-check-screens/run.py <検証環境> <ポート> <撮る先>`。OTRP v64、`flat_512_left_v64`、温帯（x<256）、昼夜は止めてある。車両はダイヤの積載の待ちを 100% にして停留所・駅で止める。街の建物は夏まで進めた後に置く（早送りの間に建て替わるため）。木は成木（`age` 576 以上）になるまで植え直す。
3. `annotate.py <撮った所> <出す先>` で、見出しと寸法の札を書き込み、道路・線路の帯の幅の図を作る。
4. 大きくした試し絵は `bigger.py <検証環境> <ポート> <出す先>`（撮った `bigger_z3.png` に ①〜④ の札を手で書き込んだ物が `F_bigger_bus.png`）。

置けた物・止まった車両は `2026-11-26_scale-check-screens/run.log`。画面の大きさは `measure.py <撮った所>`（素材の絵を画面の中から探す）。

## 見たこと

### 道路に対して車両が細い（いちばん大きいずれ）

- `ami_road_local` の舗装はタイルの端まで（約 26〜27m 相当。AMI の描く道具 `blender/round_road4.py` の説明では、白線の外はタイルの端までが路肩）。白線の外から外は 88px = 約 18m 相当で、**1 車線が約 9m** になる。
- そこを走るバスは、屋根の幅が約 13px（約 2.7m。実物 2.5m）。**車線 約 44px に対して車体 約 13px** で、車両が道路に対して細く小さく見える。実物の車線（3〜3.5m）の約 2.6〜3 倍。
- 今の決まりは「道路・線路の幅は AMI が決め、pak256 の側は合わせる」（[standards.md](../standards.md) の 4 章。2026-11-25、ユーザー）。その後、「当面は AMI を使い、pak256 の規格ができたら道路・線路なども pak256 専用のアドオンとして作る」と決まった（[roadmap.md](../roadmap.md) の「進め方」。2026-11-26、ユーザー）。**道路の幅は、pak256 の道路を作るときに直せる**。
- pak256 のバス停・荷役所は、道路の幅を約 9m（c = 0.33〜0.67）と見て c = 0.74〜0.98 に置いたため、**歩道と待合が白線の上（AMI の舗装の上）に乗っている**（`E_width.png` の下）。
- 測った道路は `ami_road_local` だけ。AMI のほかの道路の種類の幅は見ていない。
- 線路（`ami_rail_ballast`）の帯は、法面を含めて 49px（約 10m 相当）。[stations.md](../stations.md) の見立て（約 3.4m）は道床の上面で、比べる所が違うので、この数字からは広い・狭いを言わない。駅のホームと道床の重なりは測っていない。

### 自前の物どうしの釣り合い

- 画面の中の絵は素材の PNG と画素まで一致した（`measure.py`。一致 100%）。拡大 3 は絵の等倍。
- 成木の高さ: ケヤキ 106px（期待 18m × 5.9 = 106）、スギ 141px（期待 142）、シラカバ 83px（期待 83）。バスの絵の外接枠は 68×53px。建物の寸法は画面では測っていない。
- 見た目では、バス（11.55m）は戸建て（9×7m）より長く集合住宅（22m）の半分ほど、トラック（6.6m）は戸建てより小さい。大きさの順におかしい所は見当たらない。
- 1×1 の街の建物は、タイル（26.4m 四方）の中で小さく見え、街並みはすき間が多い（戸建て 9×7m はタイルの面積の約 9%）。実物比例にした結果。

| (a) 1.65m のまま、車両も変えない | 道路の細さは pak256 の道路（車線を実物の幅で描く）で直す | 描き直さない。手本より細いまま |

## 手本の 2 倍の試し絵（鉄道は pak128.Japan、自動車は pak128）

上の案を出した後、ユーザーから指示があった（2026-11-26）: 「128JPスケールという設定なので2倍サイズでよさそう。自動車はJPは128に比べて小さめなので鉄道はJPの2倍、自動車は128の2倍で試してみて。」**まだ決定ではなく、試してから決める。** 素材と `standards.md` は変えていない。

### 見たこと

- **自動車の `length`**: 絵の長さに合わせて 9・6・8 にした。`length` は後ろの車両との間隔になるので、絵と合わせると継ぎ目にすき間も重なりも出ない。pak128 の 3 つの手本は dat に `length` が無く既定の 8 だが、絵は 8 単位（約 91px）より短い物がある（`Mail_Truck_2` を 2 倍して 68px = 6 単位）ので、8 にそろえるとすき間が空く。
- 自動車は長さも実物の換算から外れる（バス 12m が 14.9m 相当、郵便と石炭の 7m が 9.9m と 13.2m 相当）。「車両は実物の長さに比例」（[concept.md](../concept.md) の C）を、自動車だけ別の換算にする決定になる。列車は長さが変わらない。
- 石炭のトラックは、戸建て（9×7m）より長く、高さ 4.9m 相当になる。道路の上では見分けやすい。
- 道路の車線（約 9m）に対して、バスの幅は 3.2m 相当（約 36%）。細さは和らぐが残る（道路の幅は pak256 の道路で直せる）。
- 列車の幅は 4.1m 相当で、道床の見立て（約 3.4m）より広い。駅のホームの縁（タイルの c = 0.66、線路の中心から約 4.2m）まで、車体の側面（中心から約 2.0m）との間は約 2.2m あり、当たらない（今は約 2.8m。計算）。画面でも車体がホームに食い込む所は見えない（`J_platform_2x.png`）。ホームの屋根は今の絵と同じく車体の下側に重なる。
- 曲がり・斜め・坂、複数の編成のすれ違いは見ていない。
