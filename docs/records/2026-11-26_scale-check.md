# 縮尺（1 単位 = 1.65m）の見比べ（2026-11-26）

[#104](https://github.com/128-bit-net/pak256/issues/104)。車両・街の建物・駅・停留所・産業・成木を同じ地図に並べ、昼の画面で釣り合いを見た。**縮尺を確定するのはユーザー**で、この記録は材料と案。

## 手順

1. `python -X utf8 tools/build.py` で組む（AMI の 256 版 `ami-256-alpha.5` を含む）。
2. `python -X utf8 docs/records/2026-11-26_scale-check-screens/run.py <検証環境> <ポート> <撮る先>`。OTRP v64、`flat_512_left_v64`、温帯（x<256）、昼夜は止めてある。車両はダイヤの積載の待ちを 100% にして停留所・駅で止める。街の建物は夏まで進めた後に置く（早送りの間に建て替わるため）。木は成木（`age` 576 以上）になるまで植え直す。
3. `annotate.py <撮った所> <出す先>` で、見出しと寸法の札を書き込み、道路・線路の帯の幅の図を作る。

置けた物・止まった車両は `2026-11-26_scale-check-screens/run.log`。画面の大きさは `measure.py <撮った所>`（素材の絵を画面の中から探す）。

## 見たこと

### 道路に対して車両が細い（いちばん大きいずれ）

- `ami_road_local` の舗装はタイルの端まで（約 26〜27m 相当。AMI の描く道具 `blender/round_road4.py` の説明では、白線の外はタイルの端までが路肩）。白線の外から外は 88px = 約 18m 相当で、**1 車線が約 9m** になる。
- そこを走るバスは、屋根の幅が約 13px（約 2.7m。実物 2.5m）。**車線 約 44px に対して車体 約 13px** で、車両が道路に対して細く小さく見える。実物の車線（3〜3.5m）の約 3 倍。
- 決まりは「道路・線路の幅は AMI が決め、pak256 の側は合わせる」（[standards.md](../standards.md) の 4 章。2026-11-25、ユーザー）。合わせる手は下の案のとおり。
- pak256 のバス停・荷役所は、道路の幅を約 9m（c = 0.33〜0.67）と見て c = 0.74〜0.98 に置いたため、**歩道と待合が白線の上（AMI の舗装の上）に乗っている**（`E_width.png` の下）。
- 線路（`ami_rail_ballast`）の帯は、法面を含めて 49px（約 10m 相当）。[stations.md](../stations.md) の見立て（約 3.4m）は道床の上面で、比べる所が違うので、この数字からは広い・狭いを言わない。駅のホームと道床の重なりは測っていない。

### 自前の物どうしの釣り合い

- 画面の中の絵は素材の PNG と画素まで一致した（`measure.py`。一致 100%）。拡大 3 は絵の等倍。
- 成木の高さ: ケヤキ 106px（期待 18m × 5.9 = 106）、スギ 141px（期待 142）、シラカバ 83px（期待 83）。バスの絵の外接枠は 68×53px。建物の寸法は画面では測っていない。
- 見た目では、バス（11.55m）は戸建て（9×7m）より長く集合住宅（22m）の半分ほど、トラック（6.6m）は戸建てより小さい。大きさの順におかしい所は見当たらない。
- 1×1 の街の建物は、タイル（26.4m 四方）の中で小さく見え、街並みはすき間が多い（戸建て 9×7m はタイルの面積の約 9%）。実物比例にした結果。

## 案

| 案 | 中身 | 得るもの・失うもの |
|---|---|---|
| **(a) おすすめ: 1.65m のまま** | 車両が道路に対して細く見えるのは受け入れる。停留所の置き場所（と必要なら車線のずれ）だけ、AMI の舗装の幅に合わせて別の issue で直す | 描き直しは停留所だけ。pak128.Japan と同じ値のまま |
| (b) 単位を変える | 車線 9m を 3.5m に合わせるには、画面の物を約 2.6 倍にする（1 単位 約 0.65m）。1 タイルが約 10m になる | 22m の建物が 1×1 に入らず、`length`・セル・足跡の決まりを作り直す。成り立たない見込み |
| (c) 長さは 1.65m、車両の幅と高さだけ誇張する | 車線に合わせて車両を太らせる | 車両の見え方は良くなるが、[concept.md](../concept.md) の C（実物比例）を変える。建物・木・駅との比が崩れる |

小さな変更（例 1.5m）は、物が約 1.1 倍になるだけで道路のずれは残り、22m の建物が 1 タイル（24m）ぎりぎりになるので、案に入れない。

### 変える場合に直す物

| 直す物 | 中身 |
|---|---|
| `tools/vehicles.py` の `M_PER_UNIT` | 車両の `length`・描画位置・セル。道路の車両（`draw_vehicles.py`・`draw_bus.py`）と線路の車両（`draw_trains.py`）の描き直しと表 |
| `draw_buildings.py` の `TILE_M`・`PX_Z` | 街の建物 11 種と季節の絵。産業（`draw_industry.py`）・停留所・駅（`draw_stops.py` 2 つ）・信号（`draw_signal.py`）も同じ値を前提にしている |
| `draw_trees.py` の定数（`PX_H` など） | 木 8 種 |
| `objects/gui/logo.py` | 起動のロゴの気動車の大きさの比 |
| 検査 | `test_vehicles.py`・`test_trees.py` などの期待値 |
| 文書 | `standards.md` 全体、`vehicles.md`・`buildings.md`・`trees.md`・`stations.md`・`industry.md` の寸法 |

AMI の道路・線路は pak256 の縮尺に合わせて描いていないので、描き直しの対象に入らない。

## 確かめていないこと

- 道路・線路の軸の向きの片方（東西）だけを撮った。ほかの向き・曲がり・坂は見ていない。
- 雪の気候と冬の絵での釣り合い。
- 拡大 3 と 6 以外。
- `sample_bus` と、砂漠・熱帯などの木 5 種は並べていない。
- 線路の道床の幅は、画面の 1 列の色の切れ目で測った値（法面を含む）。駅のホームと道床の重なりは測っていない。
