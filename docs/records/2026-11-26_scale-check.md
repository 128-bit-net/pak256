# 縮尺（1 単位 = 1.65m）の見比べ（2026-11-26）

[#104](https://github.com/128-bit-net/pak256/issues/104)。車両・街の建物・駅・停留所・産業・成木を同じ地図に並べ、昼の画面で釣り合いを見た。**縮尺を確定するのはユーザー**で、この記録は材料と案。

## 手順

1. `python -X utf8 tools/build.py` で組む（AMI の 256 版 `ami-256-alpha.5` を含む）。
2. `python -X utf8 docs/records/2026-11-26_scale-check-screens/run.py <検証環境> <ポート> <撮る先>`。OTRP v64、`flat_512_left_v64`、温帯（x<256）、昼夜は止めてある。車両はダイヤの積載の待ちを 100% にして停留所・駅で止める。街の建物は夏まで進めた後に置く（早送りの間に建て替わるため）。木は成木（`age` 576 以上）になるまで植え直す。
3. `annotate.py <撮った所> <出す先>` で、見出しと寸法の札を書き込み、道路・線路の帯の幅の図を作る。

置けた物・止まった車両は `2026-11-26_scale-check-screens/run.log`。

## 見たこと

### 自前の物どうしの釣り合い

- 車両・建物・木・駅は同じ換算で描いてあり、画面の上でも寸法どおりだった。木の高さの実測（画面の画素）: ケヤキ 106px（期待 18m × 5.94 = 107）、シラカバ 83px（期待 83）、スギ 142px（期待 143）。
- バス（11.55m）は戸建て（9×7m）より長く、集合住宅（22m）の半分。トラック（6.6m）は戸建てより小さい。気動車 2 両（約 40m）は 1.5 タイル。大きさの順におかしい所は見当たらない。
- 1×1 の街の建物は、タイル（26.4m 四方）の中で小さく見え、街並みはすき間が多い（戸建て 9×7m はタイルの面積の約 9%）。これは縮尺を実物比例にした結果で、pak128.Japan と同じ考え方。
- 車両は建物や道路に比べて細く小さい（バスの高さ 3.2m = 19px）。256px のタイルなので、形は見分けられる。

### AMI の道路・線路との釣り合い（縮尺では直らないずれ）

- `ami_road_local` の舗装はタイルのほぼ全幅（約 27m 相当）、白線の外から外は約 18m 相当。この縮尺の実物の 2 車線道路（7〜10m）の 2 倍以上。1.65m を変えて合わせようとすると、1 単位が 1m を大きく下回り、建物がタイルに収まらなくなる。
- 線路（`ami_rail_ballast`）の道床の帯は約 10m 相当で、[stations.md](../stations.md) の見立て（約 3.4m）より広い。
- pak256 のバス停・荷役所は、道路の幅を約 9m（c = 0.33〜0.67）と見て c = 0.74〜0.98 に置いたため、**AMI の舗装の上（白線の上）に歩道と待合が乗っている**（`E_width.png` の下）。駅も同じ見立て（道床 約 3.4m）で置いてあり、ホームが道床に掛かっているかは、この撮影では測っていない。

## 案: 1.65m のままにする

- 自前の物どうしの釣り合いは取れていて、変える理由が画面に出ていない。
- 小さくすると（例 1.5m）物は約 1.1 倍に大きく見えるが、道路の幅のずれは残る。1×1 の建物の大きい物（22m）は、1 タイル（1.5m なら 24m）にぎりぎりになる。
- pak128.Japan と同じ値で、移る人が数値を流用できる。
- 道路の幅のずれは、縮尺ではなく AMI の道路の幅と、停留所の置き場所の問題。別の issue にする。

## 確かめていないこと

- 道路・線路の軸の向きの片方（東西）だけを撮った。ほかの向き・曲がり・坂は見ていない。
- 雪の気候と冬の絵での釣り合い。
- 拡大 3 と 6 以外。
- `sample_bus` と、砂漠・熱帯などの木 5 種は並べていない。
- 線路の道床の幅は、画面の 1 列の色の切れ目で測った値（法面を含む）。駅のホームと道床の重なりは測っていない。
