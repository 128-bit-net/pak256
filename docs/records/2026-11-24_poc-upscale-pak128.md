# pak128 を 2 倍にした pak256 の起動の試し（2026-11-24）

[concept.md](../concept.md) の 4 章の 1。本体が 256px のタイルの pak セットを読めるか、どれだけ重くなるかを確かめた。

## やったこと

- pak128（`simutrans/pak128` の 2.10.3）のソースの絵を、最近傍で 2 倍にした。dat の絵の参照に付いた画素のずらし（`file.0.0,x,y`）も 2 倍にした。道具は [tools/poc_upscale_pak128.py](../../tools/poc_upscale_pak128.py)。
  - GUI の小さなアイコン（`base/misc_GUI_64`）は拡大せず、元の `PAK64` のまま組んだ。
  - 煙の位置（`SmokeOffset`）と標識の `offset_left` は変えていない。本体が pak の大きさに合わせて縮尺すると読んだため（`simfab.cc` の 1649 行付近で `OBJECT_OFFSET_STEPS` を掛けている 1 行を読んだだけ）。どちらもゲームで確かめていない。
- makeobj で、元が 128 の物は `PAK256`、176 の物は `PAK352`、250 の物は `PAK500` で組んだ。どのフォルダも makeobj は終了コード 0 で終わった（`quiet` で動かし、出力は残していないので、警告の有無は分からない）。
- OTRP v64（`sim-WinGDI64-OTRPv64.exe`）で、保存データを指定せずに起動した。本体が作る 64×64 の既定の地図（街 1・工場 3）で、pak128 と比べた。追加のアドオンは読まない（`-noaddons`）。

## 結果

| | pak128 | pak128 を 2 倍（pak256） | 比 |
|---|---|---|---|
| pak のファイルの合計 | 409MB | 1.6GB | 約 4 倍 |
| 起動して地図が出るまで（粗い測定） | 約 3 秒 | 約 5 秒 | — |
| メモリ（ワーキングセット） | 475MB | 1695MB | 約 3.6 倍 |

- 起動した。画面に写った地面・水・道路・街の建物・木・影は、タイルの格子に合って描かれた。ツールバーのアイコンは元の大きさのまま。
- メモリの増えた分はほぼ絵で、地図の広さにはあまり依らないはず（未確認）。64 ビット版なら 1.7GB は動く範囲。
- 起動の時間は、1 秒ごとにメモリを見て、増え方が 3 秒続けて 1% 以内に収まった時点までで測った。±1 秒ほどの粗い値。

## 確かめていないこと

- 線路・車両・駅・橋の見た目。画面に写っていないので、絵のずらしを 2 倍にした処理が正しいかは確かめていない。
- 描画の速さ。起動直後は歓迎の窓（モーダル）が開いていて、その間は MCP が動かず、画面を動かせなかった。
- 広い地図・多くの車両を走らせたときの重さ。
- ズームを引いたときの見た目と速さ。
- 本家 125.0.1 での起動。

## 試し方の注意

- `addon_check` は、終了時に自動保存し、次の起動で読み込む設定になっている（`reload_and_save_on_quit`）。保存データを指定せずに起動すると、本体は `autosave-<pak の名前>.sve` を `temp-load.sve` に改名して読み込む。その後、次に起動したときに `temp-load.sve` を消す（`simmain.cc` の 1423 行付近）。そのため、強制終了すると自動保存は元に戻らず、次の起動で消える。この試しで `autosave-pak128.sve` を失った。
- 次から pak256 の試しは、`addon_check` を写した専用の作業フォルダ（`-set_workdir`）で行うか、保存データを `-load` で指定して起動する。
