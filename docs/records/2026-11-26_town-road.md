# 街の道路が base_single の絵になる理由（2026-11-26）

[#147](https://github.com/128-bit-net/pak256/issues/147)。[#141 の記録](2026-11-26_snow-road-seam.md)で残った「保存データの設定によるのか、本体の置き換えなのか」を調べた。pak256 の設定・dat は変えていない。

## 結論

- **両方が重なっている。** 確かめに使う保存データ `flat_512_left_v64` は pak128 の道路の名前を持っていて、pak256 にその道路が無いので、本体が代わりの道路を選ぶ。代わりの選び方が `ami_road_local` と `ami_road_local_base_single` の同点になり、`base_single` が先に当たる。
- `base_single` が街の道路になるのは、意図したものではない。AMI の基盤の版は壁を重ねて敷くための版（AMI の `docs/objects/road.md` の「地上の基盤の版」）。
- pak256 で新しく作った地図では `ami_road_local` になる見込み（本体のコードと、名前を書き換えた保存データでの確かめ。新しい地図そのものは確かめていない）。
- pak256 の設定は直さなくてよい。

## 街が敷く道路の指定

| ファイル | 指定 |
|---|---|
| `config/simuconf.tab` | `city_road[0] = ami_road_local,0,2999`。道路の名前を指定するのはここ |
| `config/cityrules.tab` | 道の延ばし方・建物の置き場の形だけで、way の名前は無い |
| `config/menuconf.tab` | `general_tool[36]`（街の道路の道具）をツールバーに置くだけで、way の名前は無い |

街の道路の道具（`simtool.cc` の `tool_build_cityroad::get_desc`）と、街が建てる道（`simcity.cc` の 4125 行目あたり）は、どちらも本体が持つ 1 つの「街の道路」（`karte_t::get_city_road`）を使う。歩道は way の絵とは別の印で、街の道路の道具と街が付ける（`set_build_sidewalk`・`set_gehweg(true)`）。`base_single` だから歩道が付くのではない。

## 本体の選び方

本体のコードは OTRP の fork の `5505075fd`（`feature/script-save`）を読んだ。ゲームの実行ファイル（OTRP v64）と同じコミットかは確かめていないので、動きの根拠は下の「ゲームでの確かめ」。

1. **名前の一覧は保存データが持つ。** `settings_t::rdwr` が `city_roads` の名前・登場年・退役年を保存し、読むときに置き換える（`dataobj/settings.cc` の 670〜690 行）。読み込みで自動に `simuconf.tab` で上書きする処理は見当たらなかった。設定の窓の「Simuconf.tab」のボタンは手で読み直せるが、道路の名前だけでなく設定を丸ごと作り直す（`gui/settings_frame.cc` の 77〜98 行）。
2. **名前に当たる道路が無ければ飛ばす。** `get_timeline_road_type` は、pak に無い名前を飛ばし、全部無ければ `NULL`（`settings.cc` の 2248〜2279 行）。
3. **代わりを探す。** `karte_t::recalc_average_speed` が `weg_search(road_wt, 50, …)` を呼ぶ（`simworld.cc` の 4240〜4256 行）。年代設定が有効でも無効でも同じ。
4. **同点は入れ物の順。** `weg_search` は 50km/h 以下で一番速い道路を選び、同じ速さなら先に見た物を残す（`bauer/wegbauer.cc` の 166〜189 行。高架の版は種類が違うので入らない）。見る順は名前のハッシュ表の順で、名前の先頭 16 文字の和を 101 で割った余り（`tpl/stringhashtable_tpl.h`・`tpl/hashtable_tpl.h`）。`ami_road_local_base_single` は 23、`ami_road_local` は 32 なので、`base_single` が先に当たる。

2 つの way は、速さ 40km/h・1900 年登場まで同じ（AMI の `blender/ami_dat.py` は、基盤の版に通常の版と同じ値を入れる）。

[saved_roads.py](2026-11-26_town-road/saved_roads.py) で読んだ `flat_512_left_v64`（出力は [saved_roads.log](2026-11-26_town-road/saved_roads.log)。先頭の行は `Simutrans 0.122.0.64-pak128`）:

| 一覧 | 名前（登場〜退役） |
|---|---|
| 街の道路 | `CityRoad_030`（0〜1910）、`Road_040`（1910〜1950）、`Road_050`（1940〜2999） |
| 街どうしの道路 | `Road_070`、`Road_090`、`Road_055`、`Road_030` |

pak256 と AMI の道路には、どの名前も無い。

## ゲームでの確かめ

OTRP v64、`flat_512_left_v64`（1930 年）、AMI は `ami-256-alpha.7`。[check.py](2026-11-26_town-road/check.py)（出力は [check.log](2026-11-26_town-road/check.log)。起動と終了の行は除いた）。

| 場面 | 街の道路の道具 | 街を置いた後の地図の道 |
|---|---|---|
| 保存データのまま | `ami_road_local_base_single`・歩道つき | 全部 `ami_road_local_base_single`・歩道つき |
| 写しの街の道路の名前 3 つを `ami_road_local` に書き換え | `ami_road_local`・歩道つき | 全部 `ami_road_local`・歩道つき |

書き換えたのは作業フォルダの写しだけで、検証環境の保存データは変えていない。

## 当てはまる場面

- **pak256 の pak で作っていない保存データ**（pak128 などで作った物）を pak256 で読むと、保存された名前が無いので `base_single` になる。確かめ用の `flat_512_left_v64` もこれ。この保存データで撮った街の道路の画面は、新しい地図の街の道路とは絵が違う。
- **道路の登場年（1900 年）より前に始めた地図**も、代わりの選び方を通るので `base_single` になる見込み（`weg_search` を読んだだけ）。開始年の既定は 1930 年。
- そういう保存データでは、街が建物の周りの道を今の街の道路に置き換えるので（`simcity.cc` の `update_city_street`。道の種類か歩道が違い、置き換えを禁じていない道。持ち主がいれば公共になる）、プレーヤーが敷いた `ami_road_local` も街のそばでは `base_single` になる（コードを読んだだけ）。
- **pak256 で新しく作る地図**は、`simuconf.tab` を読んだ設定（`env_t::default_settings`）をそのまま使う（`gui/welt.cc` の 525 行）。`city_road[0]` の行があると、前に残った一覧（`settings.xml`）は捨てて入れ直す（`settings.cc` の 1590〜1592 行）。

置き換えそのものは新しい地図でも働くので、街の建物の脇に敷いた `ami_road_general` などは `ami_road_local` になる見込み（コードを読んだだけ。本体の元からの動きで、pak256 の指定の問題ではない）。

雪の気候の道のタイルの境目の暗い線（[#141](2026-11-26_snow-road-seam.md)）は `base_*` の絵にあるので、新しい地図の街の道路には出ない見込み。`base_single` を手や壁と一緒に敷いた所には出る。

## 直しの案（この issue では直さない）

1. **pak256 の設定・dat は変えない**（おすすめ）。新しい地図の指定は合っていて、保存データが持つ名前は pak の側から変えられない。
2. **確かめ用の街の道路を通常の版にする**: 街の道路の画面を撮る確かめでは、`flat_512_left_v64` のままだと新しい地図と違う way を見ることになる。pak256 で作った保存データを用意するか、読み込む写しの名前を書き換える（`check.py` の `rename_city_roads` の形）。`tools/` か検証環境の変更になる。
3. **AMI の側で同点をなくす案はすすめない。** `weg_search` が道路どうしを比べるのは速さと年代だけ（ほかは way の種類とツールバーの絵の有無で絞る）なので、基盤の版の速さを下げる（値が変わる）か、名前を変えてハッシュの順を変える（本体の中の並びに頼る）ことになる。

## 確かめていないこと

- 新しく作った地図でどの way になるか。本体は起動画面の間 MCP に答えない（[ゲームでの確認の道具](../game-check.md)）。存在しない保存データ名で起動して本体の既定の地図を使う形も 1 回試したが、120 秒の間 MCP が答えなかった。
- 1900 年より前の開始、`update_city_street` の置き換え、街どうしの道路の代わり（`weg_search(road_wt, 80, …)`）。コードを読んだだけで、ゲームでは見ていない。
