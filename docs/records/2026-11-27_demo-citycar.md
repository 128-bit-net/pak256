# 初期マップ demo.sve の街の車の値を合わせた（#194）

2026-11-27、OTRP v64（`sim-WinGDI64-OTRPv64.exe`）、Windows の GDI 版。手順は [layout.md](../layout.md) の「街の車の値を合わせる」。

## 何をしたか

[#182](https://github.com/128-bit-net/pak256/issues/182) で `config/simuconf.tab` を `citycar_level = 8`・`default_citycar_life = 36` にしたが、保存データは自分の値を持つので、`demo/demo.sve` は 5・120 のままだった。`tools/demo_citycar.py --write` で、展開した中身の 2 つの整数だけを書き換えた。

| | 前 | 後 |
|---|---|---|
| 交通量（`citycar_level`） | 5 | 8 |
| 寿命（`default_citycar_life`） | 120 | 36 |
| 大きさ（gzip） | 688,660 バイト | 512,810 バイト |
| SHA-256 | `44470b3a33db6dbe84d64b0128265381a82da1431b1da5f69d124cdbe022bb3d` | `db69d083c1073f7d795b6d30be12fde3d7fd4f11ca8e1bd49825ab028f7e5ffe` |

- 展開した中身（3,115,839 バイト）の違いは 2 バイトだけ。大きさが減ったのは、gzip の詰め直しの違い。
- ゲームで読み直して保存し直す方法は取らなかった（画面の位置・車両の位置などが変わるため。寿命を変えるゲームの中の手も見つけていない）。

## 確かめたこと

pak は main の `71a8499` を AMI（`ami-256-alpha.9`）も入れて組んだ。保存データの道路名は書き換えずに読んだ（`rewrite_roads=False`）。

- 前と後の `demo.sve` をそれぞれ `-load` で読み、スクリプトの `settings.get_traffic_level()` と、ゲームが保存し直した物の中身を読んだ。前は 5・5・120、後は 8・8・36（順に、スクリプトの交通量・保存し直した交通量・寿命）。
- 保存し直した物を同じ道具で読むだけでは、寿命の位置の誤りに気づけない。そこで本体の動きでも確かめた。交通量を 0 にして寿命だけ変えた 2 つの写しに、街の車（`pak256_citycar_sedan`）を 40 台置いて 11 か月進めると、寿命 1 は 0 台、寿命 36 は 40 台が残った。
- 場所を読んだ本体のソースは手元の v63。v64 のソースは読んでいない（v64 では上の動きと値で確かめた）。
- 後の `demo.sve` を `-load` で読んだ画面に「足りない物」の窓は出なかった。
- `-load` を付けない起動（`tools/title_shot.py`）で、起動の窓の後ろに地図が映り、「足りない物」の窓は出なかった。
- `tools/check_demo.py`: 52 個の名前が全部 `build/pak/` にある。
- 地図の地面に、街の車は 0 台。残りの寿命を持ったままの車は無い。

## 確かめていないこと

- 地図を何か月も進めて、街の車が出て消えること（値の効き方は [#182 の記録](2026-11-27_citycar-level.md)）。
- 起動の窓の「ゲームの再開」などを押した後の動き。
- v64 以外の本体。
