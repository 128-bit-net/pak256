# 道路の停留所（AMI の物）と線路の駅（pak256 の物）

道路の停留所（バス停・荷役所）は、仮の物（`pak256_bus_stop`・`pak256_truck_stop`。[#44](https://github.com/128-bit-net/pak256/issues/44)）を [#72](https://github.com/128-bit-net/pak256/issues/72) で消し、AMI の 256 版の `ami_road_bus_stop`・`ami_road_truck_stop`（`ami-256-alpha.3` の `ami_road.pak`。128na/simutrans-addon-dev#277。[layout.md](layout.md) の「AMI の 256 版を同梱する」）に置き換えた。pak256 には道路の停留所を置かない。ゲームでの確かめは [記録](records/2026-11-25_ami-road-stops.md)。

| AMI の物の `name` | 扱う貨物 | 置き換えた仮の物 |
|---|---|---|
| `ami_road_bus_stop` | 旅客（`enables_pax`）・郵便（`enables_post`） | `pak256_bus_stop`（バス停） |
| `ami_road_truck_stop` | 貨物（`enables_ware`。旅客・郵便は扱わない） | `pak256_truck_stop`（トラックの荷役所） |

- どちらも `type=stop`・`waytype=road`・`level=2`（仮の物と同じ）。AMI の物は建設費（`cost=80000`）と維持費（`maintenance=3600`）を持つ（仮の物は値を書いていなかった）ので、費用の面は変わる。画面の名前は AMI の側（`ja_ami.tab`）が持つ（日本語のみ。英語の画面では物の名前のまま出る見込みで、ゲームでは未確認。pak256 の `text/` には書かない）。
- カーソル: AMI の停留所の `cursor=` には位置の指定が付いておらず、置くときにカーソルの絵がずれる。既知で、[#76](https://github.com/128-bit-net/pak256/issues/76)・AMI の 128na/simutrans-addon-dev#282 で直す。
- **保存データへの影響**: 保存データは物の名前で引くので、仮の停留所（`pak256_bus_stop`・`pak256_truck_stop`）を置いた保存データを今の pak256 で読むと、その名前の物が無い。α0.2（v0.2.0）・α0.3（v0.3.0）の保存データは、仮の停留所を置いてあれば、その停留所が消える見込み（建物の名前が見つからないと外される、というコードの読み。OTRP 系のソース `gebaeude_t::rdwr` で読んだもので、125.0.1 そのものではなく、置いて確かめてはいない）。停留所の枠（`haltestelle_t`）と、ダイヤが指す停留所がどうなるかは未確認。Release の説明に「保存データの停留所は置き直し」と書く。
- 線路の駅（下）は pak256 の物。AMI は駅を作らない（2026-11-26、ユーザー。128na/simutrans-addon-dev#279 は作らずに閉じた）。

## 線路の駅（pak256 の物）

線路の駅は、[#46](https://github.com/128-bit-net/pak256/issues/46) で仮に置いた物を、[#73](https://github.com/128-bit-net/pak256/issues/73) で pak256 の駅として使い続けることにした（2026-11-26、ユーザー。pak256 は基本のアドオンを自分で作り、当面は絵より動くことを優先する。[roadmap.md](roadmap.md) の「進め方」）。AMI の物に置き換えない。物の名前（`pak256_train_station`）は変えなかったので、保存データは今までどおり読める。絵は簡単な物（箱を数式で描いた物）で、pak128 の絵は使っていない。

置き場は `objects/station/rail_stops/`（駅）。`draw_stops.py`（MIT）が PNG と表（`.yaml`）を書き出す。直すときはスクリプトを直して流し直す（`python -X utf8 objects/station/rail_stops/draw_stops.py`。Pillow が要る）。線路の信号は [signals.md](signals.md)。

## 駅の表

| `name` | `obj` | `type` | `waytype` | 扱う貨物 | 画面の名前（ja / en） |
|---|---|---|---|---|---|
| `pak256_train_station` | `building` | `stop` | `track` | 旅客（`enables_pax`。郵便・貨物は扱わない） | 駅 / Train Station |

- 1x1 タイル、`level` 2（容量。本体は level × 32。値は仮）、登場年 1900（仮）、`allow_underground` 2、`noinfo` 1。
- 駅（`pak256_train_station`）: 線路（AMI の `ami_rail_ballast`）の脇に、高さ 0.9m のホームと屋根つきの待合を置く。線路はタイルの中央（c = 0.43〜0.57。道床の幅 約 3.4m）を通ると見て、近い側（c = 0.66〜0.98）にホームを置いた。向きの絵・シートの並びは下の「向きの絵」のとおり。**列車は 2 両で 24 単位 = 1.5 タイルあるので、駅は 2〜3 タイル並べて置く**（1 タイルだと編成がはみ出す）。ゲームで 3 タイルを並べ、気動車 + 付随車が停まって旅客を積み降ろしできた（[記録](records/2026-11-25_rail-train.md)）。信号と一緒の確かめは [記録](records/2026-11-26_rail-signal.md)（上の辺と下の辺に 3 タイルずつ置き、4 編成が周回して停まった）。

## 向きの絵

駅の dat は、向きに応じて 8 通りの絵を持つ（本体の決まり。`dims` の 3 つめが 8）。「端」は線路の行き止まりでなく、並んだ駅の連なりの端で、1 つだけ置くと両端（6・7）の絵が出る（ゲームで確かめた）。端の絵は、帯の端に小さな縁を置くだけで、線路はふさがない。

| 番号 | 向き |
|---|---|
| 0 | NS（左下〜右上の向き）の中ほど |
| 1 | EW（右下〜左上の向き）の中ほど |
| 2 | NS の南端 |
| 3 | EW の東端 |
| 4 | NS の北端 |
| 5 | EW の西端 |
| 6 | NS の両端（単独の駅） |
| 7 | EW の両端（単独の駅） |

- 絵は後ろ（車の下）と前（車の上）に分ける。シートは 8 列（向き）× 3 行（0 行 = 後ろ、1 行 = 前、2 行 = 道具の絵）。セルの名前は `<名前>.<行>.<列>`。
- 線路そのものは描かない（線路は AMI が持つ）。線路はタイルの中央を通ると見て、見える側（右下か左下）の脇にホームを置いた。
- 道具の絵（`icon`）は、2 行 0 列のセルの左上の角に置いた 192px の角丸の四角（地の色に、向き 0 の後ろと前を重ねた駅の絵を収めたもの。`draw_stops.py` の `tool_icon`）。192px にしたのは、本体がアイコンを `icon_height`（48）に収まる最大の倍率（192 なら 1/4 でちょうど 48）で縮めるため。四角を左上の角から隙間なく置くのは、絵に透明な所があると本体が見える範囲だけを縮めて置くため、枠がずれて灰色の空きに見えたからで、これが線路・道路のツールバーの灰色のアイコンだった（[#71](https://github.com/128-bit-net/pak256/issues/71)。記録は [records/2026-11-25_rail-leftovers.md](records/2026-11-25_rail-leftovers.md)）。`cursor` は書かない（置くときのカーソルが出るかは未確認）。

# 道路の車庫（AMI の物）

道路の車庫は、仮の物（`pak256_road_depot`。[#58](https://github.com/128-bit-net/pak256/issues/58)）を [#64](https://github.com/128-bit-net/pak256/issues/64) で消し、AMI の 256 版の `ami_road_depot`（`ami-256-alpha.2` の `ami_road.pak`。[layout.md](layout.md) の「AMI の 256 版を同梱する」）に置き換えた。pak256 には車庫を置かない。ゲームでの確かめは [記録](records/2026-11-25_ami-road-depot.md)。

- **保存データへの影響**: 保存データは建物を名前で引く。仮の車庫（`pak256_road_depot`）を置いた保存データを今の pak256 で読むと、その名前の建物が無い。本体（125.0.1）のコードの読みでは次のとおり（`gebaeude_t::rdwr`・`depot_t::rdwr_vehikel`。置いて確かめてはいない）。町の建物の名前の形でなければ、`gebaeude_t::rdwr` は「足りない pak」として記録し、タイルは空のまま抜ける。続く `depot_t::rdwr_vehikel` は「tile for depot not found」のエラーを記録したうえで、**その車庫のタイルを住宅（`city_res` の 1 つ目）に差し替え**、中の車両は普通に読み込む。つまり、仮の車庫があった場所は**住宅の見た目の車庫の入れ物**になり、中の編成は入ったまま（車両の定義が残っていれば。クリックすれば車庫の窓が開く）になるはず。町の建物として街に数えられるかは未確認。**α0.2（v0.2.0、2026-11-25 公開）は仮の車庫を含む**ので、α0.2 で車庫を置いた保存データを、この置き換えの後の版で読むと、このおかしな建物が残る。α0.2 の保存データは引き継げないと、次の版の説明（Release の本文）に書く。実際の動きは、v0.2.0 の保存データを今の pak で読んで確かめる（まだ）。
- 置いた直後は、本体が建設中の絵（黄黒の縞。`objects/gui/construction`）を出す。ゲームを進めると（AMI の車庫は置いてからゲーム内の約 100 秒。`Game.settle(20)` の速さ 64 で足りた）、車庫の絵になる。確認のときに待つ（`Game.settle`）。
