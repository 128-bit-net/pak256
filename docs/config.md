# 設定ファイル（`config/`）

本体が pak の読み込み時に読む 4 つの設定ファイルの、決めた値とその理由。置き場は [layout.md](layout.md)、縮尺の決まりは [concept.md](concept.md) の C。2026-11-25（[#3](https://github.com/128-bit-net/pak256/issues/3)）。

pak128 の値を参考にしたが、文は写さず、本体のコード（OTRP の fork の `dataobj/settings.cc`・`simcity.cc`・`bauer/vehikelbauer.cc`）で意味を確かめて書き直した。

## 検証

2026-11-25、pak128 を 2 倍にした試しの pak（[記録](records/2026-11-24_poc-upscale-pak128.md)）の `config/` をこの 4 つに差し替え、OTRP v64 を起動した（窓のある本体。MCP のポート 47841）。

- 差し替えたのは初版のとき。ツールバーの番号と空白は、レビューの指摘で直した後は再び起動していない（起動のログでは、ツールバーの誤りは警告にならないため、ログでは確かめられない）。
- 4 つとも読み込めた（初版）: `Read 5 house building rules`・`Read 3 road building rules`・`Reading speedbonus configuration` が出て、`fatal`・`bad format`・`ignored`（規則の無視）の行は無い。起動のログに設定ファイルが原因の警告は無い。
- 確かめていない: ツールバーの見た目。街の成長は #8 で、人口をスクリプトで足した形だけ見た（輸送での成長は未確認。`cityrules.tab` の節と記録）。`ami_road_local` が街の道路になることは [記録](records/2026-11-25_ami-road-screens.md) で確かめた。
- 起動中にゲームの MCP は応答しなかった（起動の最初の画面が出たまま）。そのため、街の増え方の数値は取っていない。

## `simuconf.tab`

### 256px で見直した値

| キー | 値 | 理由 |
|---|---|---|
| `tile_height` | 8（pak128 と同じ） | 高さ 1 段の画素数は `tile_height` × タイルの幅 ÷ 64（`simconst.h` の `tile_raster_scale_y`）。256px で 8 なら 32px で、タイルの幅との比（1/8）が pak128（16px / 128px）と同じ。変えると坂の傾きが変わる。 |
| `height_conversion_factor` | 2（同じ） | 本体は 1 か 2 しか受けない（`settings.cc`）。基本の坂を 1 段にするか 2 段にするかを決め、古い保存データの坂の読み替えのほか、トンネル・橋の坂の判定や高さ地図の読み込みにも使われる。#5 の坂の絵がこの値（2 段）と合っていなければならない。 |
| `diagonal_multiplier` | 724（同じ） | 斜めに進むときの長さの比。地面の菱形の縦横比（2:1）で決まり、タイルの画素数によらない。 |
| `station_coverage` | 2（同じ） | 停留所が拾うタイル数。タイルの絵が 2 倍でも、1 タイルが指す広さは変えない。 |
| `bits_per_month` | 19（同じ） | 1 か月の長さ。本体は 1 タイル当たりの速さの換算が固定で、pak が変えられるのは月の長さだけ。車両を実物の長さに比例させても換算は変わらない（下の「速さと距離」）ので、pak128 と同じにする。 |

### 道路（街が建てる道路・街どうしをつなぐ道路）

AMI の生活道路・一般道・高速の名前（`ami_road_local`・`ami_road_general`・`ami_road_expressway`、`addons/ami/src/*.dat`）を使う。

| キー | 値 | 理由 |
|---|---|---|
| `city_road[0]` | `ami_road_local,0,2999` | 街の中は生活道路（40km/h、1900 年〜）。登場年を 0 にすると、本体はその道路自身の登場年（1900 年）に置き換える。1900 年より前に始めたときは、本体が速さ 50km/h 以下の別の道路で代わりにする（街どうしは 80km/h 以下）。開始年は 1930 年なので影響しない。 |
| `intercity_road[0]` | `ami_road_local,0,1930` | 1930 年までは街どうしも生活道路。 |
| `intercity_road[1]` | `ami_road_general,1930,2999` | 1930 年から一般道（120km/h）。高速道路（1990 年〜、360km/h）は街どうしの自動の道路には使わない。 |

AMI の 256 版は、`ami-256-alpha.1` では `ami_road_local`（生活道路・通常の版）だけで `ami_road_general` が無かった（以下はそのときの確かめ。`ami-256-alpha.2`（#64）の `ami_road.pak` には `ami_road_general` も入るので、街どうしの道路は一般道になる見込みで、まだ確かめていない）。無い名前のときの本体の動きは、`dataobj/settings.cc` の `get_timeline_road_type` を読んで確かめた: 名前に当たる道路が無ければ飛ばし、見つからなければ（名前の道路が無いときと、期間外のとき。`NULL`）、街の道路は `karte_t::recalc_average_speed` が `weg_search`（上限 50km/h）、街どうしの道路は `karte_t::distribute_cities` が `weg_search`（上限 80km/h）で代わりにする。`weg_search` は上限以下で一番速い道路を選び、無ければ一番遅い道路を選ぶ。AMI だけの pak では生活道路（40km/h）が選ばれる。街どうしは、開始年 1930 年では `ami_road_local` が期間外（退役 1930 年）なので、`ami_road_general` が入るまでは、この代わりの選び方を通る。止まらないので、`simuconf.tab` は直さず、`ami_road_general` の行も残す（一般道が入れば自動で使われる）。街の道路が `ami_road_local` で建つことはゲームで確かめた（タイムライン無効で。有効のときの年の判定はコードを読んだだけ）。名前が変わったらここを直す。

### 速さと距離の換算

本体の速さの換算（1 タイルを走るのにかかる時間）は pak では変えられない。車両を実物の長さに比例させる（長さ m ÷ 1.65）と、車両の絵は pak128 より長いが、同じ速さなら同じ時間で 1 タイルを走る。つまり車両の長さに対しては遅く走るように見える（車両が 1 タイルの 3/4 なら、1 タイルで 1.33 両分）。これは文書の前提からの推論で、ゲームでは見ていない。`simuconf.tab` の値では直せず、`speedbonus.tab` や車両の `speed` で釣り合いを取る範囲に収まる。ゲームで見て不自然なら、車両（#4 以降）を入れるときに決め直す。

### 値を変えなかったもの（pak128 と同じ）

街の成長（`growthfactor_*`）、旅客の出方（`passenger_factor` など）、初期の資金、建設の費用、産業の間隔、年の初め（1930 年）など。理由: concept の G（移行しやすさ）で、値段・成長の速さの感覚を保つため。車両・産業が入る前に釣り合いを動かす根拠が無い。釣り合いは、車両（#4 以降）が入ってから見直す。

### 1 タイルの広さに依存する値（決めごと）

次の値は、1 タイルが実寸で何 m かに関わるが、pak128 の 1 タイルの実寸が分からない（concept 2.3 で未確認）ため、導かずに「1 タイルが指す広さは pak128 と同じ」と決めて同じ値にした: `station_coverage`、`minimum_city_distance`、`factory_worker_radius`、`intercity_road_length`、`factory_spacing`。車両は実物比例（1 タイル = 16 × 1.65 = 約 26m）に変わるが、街・産業の広さの感覚は変えない、という判断。ゲームで街が狭い・停留所の範囲が広すぎると感じたら、ここから直す。

### 変えた・外したもの

- `river_type[0]`〜: 川の物（#5）がまだ無いので、名前を書かない。川ができたら足す。
- `max_no_of_trees_on_square` ほか木の数: pak128 と同じ。256 の絵は画素が 4 倍だが、2.1 の確かめで小さな地図は問題なかった。木の絵は #9 で入った。大きな森での描画の重さは未確認（重ければ減らす）。

## `cityrules.tab`

この物が無いと本体が起動しない（`simcity.cc` の `cityrules_init` が致命的な誤りにする）。

- 家と道路を建てる形の規則は、pak128 のもの（家 17・道路 28）を写さず、街が道路沿いに家を建て、道を延ばし、枝道を出す最小の形を自分で書いた（家 5・道路 4）。本体は規則を 90 度ずつ回して試す（`bewerte_pos`）ので、回して重なるものは 1 つにまとめた。
- 建物の種類どうしの引き合い（`res_near_*` など）と `renovation_percentage`・`minimum_city_distance` は pak128 と同じ値。
- `minimum_building_density`: OTRP は新しい綴りを、古い綴り（`minimum_building_desity`）より優先して読む。本家の最新の開発版（master）は両方を読むと確かめた。125.0.1 は未確認なので、同じ値を両方書いた。
- 規則が少ないので、街の形（区画の大きさ・道の混み方）は pak128 とだいぶ違う可能性が高い。1 タイルが 256px（実物 26m ほど）になっても、家 1 軒が 1 タイル、という前提は変えていない。
- **建物（#8）を入れてゲームで見て直した**（2026-11-25、[記録](records/2026-11-25_town-buildings.md)）。役場が 1x1 なので、本体が役場の脇に作る道は 1 タイルだけ（役場の大きさの長さの道を作る。`check_bau_townhall`）。初版の規則は「後ろに道が 2 タイル続く」前提の延長（`road_1`）しか無く、道が一度も延びなかった。しかも行き止まりの家（`house_3`）が、その 1 タイルの周りを先に家で埋めた。直したこと: 後ろに道が 1 タイルあれば延ばす規則（新しい `road_1`）を足し（元の延長は `road_2`、枝道は `road_3`、すき間は `road_4` に番号をずらした）、`house_3` は手前に道が 2 タイル続くときだけにした。

## `speedbonus.tab`

乗り物の種類ごとの、その年の標準の速さ（`vehikelbauer.cc` の `speedbonus_init`）。運賃の基準になる。値は pak128 と同じ（実在の車両の速さの経過に合わせてあるので、縮尺を変えても動かさない）。書かない種類（`maglev_track`）は、動いている車両の平均の速さがあればそれが、無ければ本体の既定値が使われる。

## `menuconf.tab`

道路・線路（#46）・街・地形の道具だけにした（モノレール・リニア・路面電車・船・飛行機・ナローゲージ・産業・送電の道具は外した。足すときは `toolbar[0]` に入口を足し、`toolbar[N]` の N は「本体が `toolbar[0]` から位置の順に読んで、参照に出会う順に 1, 2, 3…」と連番にする。本体は `toolbar[N]` を、今のツールバーの数が N に等しいときにしか作らず、飛ばすと中身が黙って捨てられる。ツールバーの行は `=` の前後に空白を入れない（空白があると本体が道具名として読まない）。ゲームの速度の `+1`・`-1`、建物の回転、停留所の併合の道具も外した）。

- アイコンの番号は pak128 の並びのまま。GUI のアイコンは `objects/gui/` にあり（[gui.md](gui.md)）、この並びで描いてある。番号を足す・変えたら、`draw_gui.py` を流し直す（使う番号を `menuconf.tab` から読む）。ツールバーの行で書いた番号は BarTools の番号、道具の行の番号は種類ごとの表の番号。
- 番号と道具の対応は、番号が同じ範囲だけを使う（下の「ツールの番号」）。
- 線路の道具（`toolbar[3]`。#46）と道路の道具（`toolbar[4]`）は、種類ごとの絞り込み（`ways(2,0)`・`ways(1,0)`、`buildings(33,2)` など）なので、AMI の線路・道路・橋・トンネル・停留所・駅・車庫がそのまま並ぶ。信号の道具（`general_tool[46]`）は入れていない（番号が本家と OTRP で違う範囲の手前だが、信号がまだ無い）。

### ツールの番号（本家 125.0.1 と OTRP の違い）

`general_tool[N]`・`simple_tool[N]`・`dialog_tool[N]` の N は、本体の `simmenu.h` の列挙の番号。本家（125.0.1）と OTRP（OTRP-KUTAv6）で、後ろのほうの番号が違う（2026-11-25、[#18](https://github.com/128-bit-net/pak256/issues/18)）。pak256 は両方を対象にする（[concept.md](concept.md) の F）ので、**番号が違う範囲は `menuconf.tab` に入れない**（どちらかに合わせると、もう一方で別の道具になる）。

| 種類 | 同じ番号（使ってよい） | 違う番号（入れない） | 本家 125.0.1 | OTRP |
|---|---|---|---|---|
| `general_tool` | 0〜47 | 48〜 | 48 ピペット・49 持ち主の設定（計 50） | 48 停留所の撤去・49 待ち貨物の消去・50 建物の所属の街の変更・51 ピペット… 57 まで（計 58） |
| `simple_tool` | 0〜35 | 36〜 | 36 地図の移動・37 全ウィンドウの巻き上げ・38 色変え・39 工場の在庫表示・40 操作の切り替え… 45 停留所の権限（計 46） | 36 道路標識の変更・37 ribi の表示・38 通知の切り替え・39 地図の移動・40 全ウィンドウの巻き上げ… 55（計 56） |
| `dialog_tool` | 0〜35 | 36〜 | 36 チャット・37 ランキング・38 道の建設窓（計 39） | 36 経路探索・37 道の編集…（計 41） |

- 出典: 本家は GitHub の `simutrans/simutrans` のタグ `125.0.1` の `src/simutrans/tool/simmenu.h`、OTRP は `128na/simutrans` の `OTRP-KUTAv6` の `simmenu.h`。列挙の番号を機械で比べた。aburch のミラーには 125.0.1 のタグが無い（master は 124.5.1 の開発版で、道具の列挙は 125.0.1 と同じ）。
- 影響: ピペット（`general_tool` 本家 48・OTRP 51）、チャット・ランキング、「全ウィンドウの巻き上げ」（`simple_tool` 本家 37・OTRP 40）などは入れられない。`toolbar` の行（`BarTools`）の番号は、この表と別（アイコンの番号）なので影響しない。
- 以前入っていた `simple_tool[40]`（OTRP では「全ウィンドウの巻き上げ」、本家では「操作の切り替え」）は、この方針で外した。
- 検査: `tools/lint_config.py` が、違う範囲の番号が `menuconf.tab` に出るとエラーにする（`TOOL_ID_LIMITS`）。本体のバージョンが変わったら、この表と `TOOL_ID_LIMITS` を見直す。
- どうしても入れたい道具が出たら、pak を本家用・OTRP 用に分けて同梱するかを別に決める。

## 書き方の検査

本体は、設定ファイルの書き方の誤り（ツールバーの行の `=` の前後の空白、`toolbar[N]` の飛び、規則の形の崩れなど）を起動のログに出さずに捨てる。そのため `tools/lint_config.py` で検査する（CI の `ci.yml` が毎回流す。手元では `python -X utf8 tools/lint_config.py`）。見る内容は道具の先頭の説明と `tools/test_lint_config.py`（わざと誤りを入れた設定で失敗することの確認）を参照（[#17](https://github.com/128-bit-net/pak256/issues/17)）。値の良し悪し（ゲームでの見え方）は見ない。

[#21](https://github.com/128-bit-net/pak256/issues/21) で、検査に足す項目を決めた。本体（OTRP の `dataobj/tabfile.cc`・`simmenu.cc`・`simcity.cc`）の読み方を確かめて合わせた。

| 項目 | 本体の読み方 | 検査 |
|---|---|---|
| 大文字・小文字 | キーは小文字にして読む（`tabfile_t::format_key`）。値の道具の名前（`general_tool[3]` など）は小文字のまま比べる（`strstart`） | キーは小文字にして検査する（大文字のキーを読み飛ばさない）。値の名前が大文字だと誤り。ルールの記号（`S` と `s` など）は元から区別している |
| 範囲の書き方 | キーの `[]` の中の `,`・`-` を 1 個ずつに展開する（`toolbar[6][10-11]` は `[10]` と `[11]`）。1 つの `[]` は 255 個まで（256 個以上になる範囲は本体が止まる） | 数字の範囲・列挙を展開してから検査する。256 個以上になると誤り。`[n,s]` のような ribi の名前と、値の `<式>` の計算は展開しない（この 2 つの設定では使わない） |
| 道具の番号の範囲外 | 本家 125.0.1 と OTRP で番号が違う範囲 | #18 の `TOOL_ID_LIMITS` で済み。足りない所は無い（定義の行・ツールバーの行の両方を見る） |
| `.chance` の値 | `get_int`（`strtol`、底は自動）で読み、`sint16` に入れる。読めない値は黙って 0 | 10 進か `0x` の整数で -32768〜32767 だけを通す。`08` のように先頭が 0 の数（8 進になる）、小数、空は誤り |
