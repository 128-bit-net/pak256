# 設定ファイル（`config/`）

本体が pak の読み込み時に読む 4 つの設定ファイルの、決めた値とその理由。置き場は [layout.md](layout.md)、縮尺の決まりは [concept.md](concept.md) の C。2026-11-25（[#3](https://github.com/128-bit-net/pak256/issues/3)）。

pak128 の値を参考にしたが、文は写さず、本体のコード（OTRP の fork の `dataobj/settings.cc`・`simcity.cc`・`bauer/vehikelbauer.cc`）で意味を確かめて書き直した。

## 検証

2026-11-25、pak128 を 2 倍にした試しの pak（[記録](records/2026-11-24_poc-upscale-pak128.md)）の `config/` をこの 4 つに差し替え、OTRP v64 を起動した（窓のある本体。MCP のポート 47841）。

- 4 つとも読み込めた: `Read 5 house building rules`・`Read 3 road building rules`・`Reading speedbonus configuration` が出て、`fatal`・`bad format`・`ignored`（規則の無視）の行は無い。起動のログに設定ファイルが原因の警告は無い。
- 確かめていない: 街の成長（家・道が建つ様子）、ツールバーの見た目、`ami_road_*` が実際に街の道路になること（試しの pak に AMI が無い）。建物（#8）と AMI の 256 版（[#266](https://github.com/128na/simutrans-addon-dev/issues/266)）が入ってから、ゲームで見て直す。
- 起動中にゲームの MCP は応答しなかった（起動の最初の画面が出たまま）。そのため、街の増え方の数値は取っていない。

## `simuconf.tab`

### 256px で見直した値

| キー | 値 | 理由 |
|---|---|---|
| `tile_height` | 8（pak128 と同じ） | 高さ 1 段の画素数は `tile_height` × タイルの幅 ÷ 64（`simconst.h` の `tile_raster_scale_y`）。256px で 8 なら 32px で、タイルの幅との比（1/8）が pak128（16px / 128px）と同じ。変えると坂の傾きが変わる。 |
| `height_conversion_factor` | 2（同じ） | 本体は 1 か 2 しか受けない（`settings.cc`）。古い保存データの坂の読み替えだけに効く。 |
| `diagonal_multiplier` | 724（同じ） | 斜めに進むときの長さの比。地面の菱形の縦横比（2:1）で決まり、タイルの画素数によらない。 |
| `station_coverage` | 2（同じ） | 停留所が拾うタイル数。タイルの絵が 2 倍でも、1 タイルが指す広さは変えない。 |
| `bits_per_month` | 19（同じ） | 1 か月の長さ。本体は 1 タイル当たりの速さの換算が固定で、pak が変えられるのは月の長さだけ。車両を実物の長さに比例させても換算は変わらない（下の「速さと距離」）ので、pak128 と同じにする。 |

### 道路（街が建てる道路・街どうしをつなぐ道路）

AMI の生活道路・一般道・高速の名前（`ami_road_local`・`ami_road_general`・`ami_road_expressway`、`addons/ami/src/*.dat`）を使う。

| キー | 値 | 理由 |
|---|---|---|
| `city_road[0]` | `ami_road_local,0,2999` | 街の中は生活道路（40km/h、1900 年〜）。開始年（1930 年）より前でも道路が無くならないよう、登場年は 0 にした。 |
| `intercity_road[0]` | `ami_road_local,0,1930` | 1930 年までは街どうしも生活道路。 |
| `intercity_road[1]` | `ami_road_general,1930,2999` | 1930 年から一般道（120km/h）。高速道路（1990 年〜、360km/h）は街どうしの自動の道路には使わない。 |

AMI の 256 版が同梱される前は、この名前の道路が無い。無い名前のときの本体の動き（既定の道路で代わりにするか）は読んでいない。起動は AMI なしでもできた。名前が変わったらここを直す。

### 速さと距離の換算

本体の速さの換算（1 タイルを走るのにかかる時間）は pak では変えられない。車両を実物の長さに比例させる（長さ m ÷ 1.65）と、車両の絵は pak128 より長いが、同じ速さなら同じ時間で 1 タイルを走る。つまり車両の長さに対して速く走るように見える。これは `simuconf.tab` の値では直せず、`speedbonus.tab` や車両の `speed` で釣り合いを取る範囲に収まる。ゲームで見て不自然なら、車両（#4 以降）を入れるときに決め直す。

### 値を変えなかったもの（pak128 と同じ）

街の成長（`growthfactor_*`）、旅客の出方（`passenger_factor` など）、初期の資金、建設の費用、産業の間隔、年の初め（1930 年）など。理由: concept の G（移行しやすさ）で、値段・成長の速さの感覚を保つため。車両・産業が入る前に釣り合いを動かす根拠が無い。釣り合いは、車両（#4 以降）が入ってから見直す。

### 変えた・外したもの

- `river_type[0]`〜: 川の物（#5）がまだ無いので、名前を書かない。川ができたら足す。
- `max_no_of_trees_on_square` ほか木の数: pak128 と同じ。256 の絵は画素が 4 倍だが、2.1 の確かめで小さな地図は問題なかった。木の絵（#9）が入ってから、重ければ減らす。

## `cityrules.tab`

この物が無いと本体が起動しない（`simcity.cc` の `cityrules_init` が致命的な誤りにする）。

- 家と道路を建てる形の規則は、pak128 のもの（家 17・道路 28）を写さず、街が道路沿いに家を建て、道を延ばし、枝道を出す最小の形を自分で書いた（家 5・道路 3）。本体は規則を 90 度ずつ回して試す（`bewerte_pos`）ので、回して重なるものは 1 つにまとめた。
- 建物の種類どうしの引き合い（`res_near_*` など）と `renovation_percentage`・`minimum_city_distance` は pak128 と同じ値。
- `minimum_building_density`: OTRP は新しい綴りを、古い綴り（`minimum_building_desity`）より優先して読む。本家 125.0.1 が古い綴りだけの可能性があるので、同じ値を両方書いた（本家のコードは未確認）。
- 規則が少ないので、街の形（区画の大きさ・道の混み方）は pak128 とだいぶ違う可能性が高い。建物（#8）が入ったところでゲームで見て、規則を足す。1 タイルが 256px（実物 26m ほど）になっても、家 1 軒が 1 タイル、という前提は変えていない。

## `speedbonus.tab`

乗り物の種類ごとの、その年の標準の速さ（`vehikelbauer.cc` の `speedbonus_init`）。運賃の基準になる。値は pak128 と同じ（実在の車両の速さの経過に合わせてあるので、縮尺を変えても動かさない）。書かない種類（`maglev_track`）は本体の既定値になる。

## `menuconf.tab`

道路・街・地形の道具だけにした（線路・モノレール・リニア・路面電車・船・飛行機・ナローゲージ・産業・送電の道具は外した。足すときは `toolbar[0]` と、番号の空いている `toolbar[]` に足す）。

- アイコンの番号は pak128 の並びのまま。GUI のアイコンは #6 で描くので、そのとき同じ並びで描く（並びを変えるなら、ここも直す）。
- 番号と道具の対応は本体の `simmenu.h`（`TOOL_*`・`DIALOG_*`）で確かめた。
- 道路の道具（`toolbar[7]`）は、種類ごとの絞り込み（`ways(1,0)`、`buildings(33,1)` など）なので、AMI の道路・橋・トンネル・停留所・車庫がそのまま並ぶ。
